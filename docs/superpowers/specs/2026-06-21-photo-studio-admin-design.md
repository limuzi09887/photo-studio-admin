# 照相馆经营管理系统 — 设计文档 V1.0

**日期：** 2026-06-21
**状态：** 已确认
**版本：** V1.0 MVP

---

## 1. 项目概述

### 1.1 项目名称

光影照相馆经营管理系统（Photo Studio Admin）

### 1.2 项目背景

当前照相馆业务流程依赖微信、Excel、本地文件夹管理，存在客户信息分散、订单进度难追踪、原图与成片管理混乱、修图流程不透明、邮件交付依赖人工、经营数据统计困难等问题。建设统一后台系统实现订单数字化、图片流程化、交付自动化、数据可视化。

### 1.3 用户画像

- **单人使用**：仅老板一人操作，无需多角色权限系统
- **设备**：PC 浏览器为主，不涉及移动端

### 1.4 业务范围

单店综合摄影：1寸/2寸证件照、签证照、身份证照、商务半身照、婚纱照、艺术写真、全家福等。

## 2. 技术方案

### 2.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端框架** | Next.js 14+ (App Router) | 全栈单体，前后端统一代码库 |
| **UI 框架** | Tailwind CSS + shadcn/ui | 组件丰富，开发效率高 |
| **ORM** | Prisma | 类型安全的数据库操作 |
| **数据库** | PostgreSQL | 关系型数据库，由 Railway 托管 |
| **文件存储** | Cloudflare R2 | 对象存储，无出口流量费，适合照片频繁查看 |
| **AI 修图** | 阿里云视觉智能 API | 证件照处理（背景切换/人脸增强/肤色匀称/亮度调整） |
| **邮件服务** | nodemailer + react-email | SMTP 发送（QQ邮箱），react-email 渲染模板 |
| **图表** | Recharts | React 图表库，轻量灵活 |
| **部署** | Railway | 一键部署，国内可访问，支持 PostgreSQL |

## 3. 产品架构

### 3.1 一级导航结构

```
🖥️ 光影照相馆后台
│
├── ① 概览          → 今日经营数据看板
├── ② 订单管理       → 订单列表 + 订单详情（8个二级模块）
├── ③ 客资          → 客户资料表
├── ④ 照片          → 今日原片集中查看
└── ⑤ 报表          → 营业数据统计
```

### 3.2 订单详情二级结构

```
订单详情
├── ① 订单摘要      → 进度条 + 基本信息 + 操作日志
├── ② 客户信息      → 客户资料编辑
├── ③ 账单/收款      → 产品明细 + 收款记录
├── ④ 原图上传      → 批量/拖拽上传原始照片
├── ⑤ 一类修片      → AI修图参数 + 原图↔修片左右对比
├── ⑥ 修图底片      → AI处理后底片管理
├── ⑦ 成片管理      → 最终精修图上传管理
└── ⑧ 邮件发送      → 模板预览 + 一键发送成片
```

### 3.3 订单状态机

```
已创建 → 已拍摄（原图已上传）→ 一类修片中 → 后期修片已完成 → 顾客可下载 → 订单结束

异常状态：已取消 | 发送失败
```

### 3.4 订单进度条（4步）

| 步骤 | 节点 | 触发条件 |
|------|------|---------|
| 1 | 已拍摄原片 | 首次上传原图 |
| 2 | 后期修片已完成 | 全部修图确认完成 |
| 3 | 顾客可下载 | 成片上传完毕 |
| 4 | 订单结束 | 邮件发送成功 |

## 4. 数据库设计

### 4.1 表结构

#### customer（客户表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | VARCHAR(100) | 客户姓名 |
| phone | VARCHAR(20) | 手机号（索引） |
| email | VARCHAR(255) | 邮箱 |
| remark | TEXT | 备注 |
| created_at | TIMESTAMP | 创建时间 |

#### order（订单表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| order_no | VARCHAR(20) | 订单号（唯一，格式：PS + yyyyMMdd + 序号） |
| customer_id | UUID → customer | 客户外键 |
| shoot_type | VARCHAR(50) | 拍摄类型 |
| amount | DECIMAL(10,2) | 订单金额（选填） |
| status | VARCHAR(20) | 订单状态 |
| appointment_time | TIMESTAMP | 拍摄日期 |
| shoot_time | TIMESTAMP | 拍摄时间（首次上传原图时间） |
| created_at | TIMESTAMP | 创建时间 |

#### order_product（产品明细表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| order_id | UUID → order | 订单外键 |
| name | VARCHAR(200) | 产品/服务名称 |
| unit_price | DECIMAL(10,2) | 单价 |
| quantity | INTEGER | 数量 |
| subtotal | DECIMAL(10,2) | 小计 |

#### payment（收款记录表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| order_id | UUID → order | 订单外键 |
| amount | DECIMAL(10,2) | 收款金额 |
| method | VARCHAR(20) | 支付方式（微信/支付宝/现金/银行转账） |
| type | VARCHAR(10) | 类型（定金/尾款） |
| paid_at | TIMESTAMP | 收款时间 |

#### order_file（文件表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| order_id | UUID → order | 订单外键 |
| file_name | VARCHAR(255) | 文件名 |
| file_url | TEXT | R2 访问 URL |
| file_size | BIGINT | 文件大小（字节） |
| file_type | VARCHAR(20) | 类型：ORIGINAL / AI_RESULT / FINAL |
| ai_params | JSONB | AI 修图参数（仅 AI_RESULT 类型） |
| created_at | TIMESTAMP | 上传时间 |

#### email_record（邮件记录表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| order_id | UUID → order | 订单外键 |
| receiver_email | VARCHAR(255) | 收件邮箱 |
| subject | VARCHAR(500) | 邮件主题 |
| status | VARCHAR(20) | 状态（成功/失败） |
| error_message | TEXT | 失败原因 |
| sent_at | TIMESTAMP | 发送时间 |

### 4.2 关键查询场景

- **手机号查订单**：`SELECT * FROM order WHERE customer_id IN (SELECT id FROM customer WHERE phone LIKE '%xxx%') ORDER BY created_at DESC`
- **客户历史订单**：`SELECT * FROM order WHERE customer_id = ? ORDER BY created_at DESC`
- **订单原图**：`SELECT * FROM order_file WHERE order_id = ? AND file_type = 'ORIGINAL'`
- **报表统计**：`SELECT DATE(created_at), COUNT(*), SUM(amount) FROM order WHERE created_at BETWEEN ? AND ? GROUP BY DATE(created_at)`

## 5. 文件上传模块

### 5.1 上传能力

| 功能 | 说明 |
|------|------|
| 批量上传 | 一次选中多张照片，逐个上传 |
| 拖拽上传 | 支持拖拽文件/文件夹到上传区域 |
| 进度显示 | 每张照片独立显示上传进度条 |
| 自动缩略图 | 上传后自动生成缩略图用于列表预览 |
| 格式支持 | JPG / PNG / HEIC / RAW（常用相机格式） |

### 5.2 上传流程

```
浏览器选择文件 → 前端压缩缩略图 → 直传 Cloudflare R2（预签名URL）
→ 返回 R2 Key → 写入 order_file 表 → 更新订单状态
```

### 5.3 文件目录结构（R2）

```
/{order_id}/
  ├── original/     ← 原图 (file_type=ORIGINAL)
  ├── ai_result/    ← AI修图结果 (file_type=AI_RESULT)
  └── final/        ← 成片 (file_type=FINAL)
```

## 6. 拍摄类型与邮件模板配置

### 6.1 拍摄类型

内嵌于订单创建流程中。默认支持类型：1寸、2寸、签证照、身份证、商务半身照、婚纱照、艺术写真、全家福。可后台灵活增减（存储在数据库配置表）。

### 6.2 邮件模板

存储在数据库，支持用户自定义编辑。默认提供 3 套模板：成片交付通知（通用）、证件照交付通知、婚纱照交付通知。模板变量由系统自动填充。

## 7. AI 修图模块

### 5.1 调用流程

```
用户选择原图 → 设置修图参数（背景色/清晰度/亮度/肤色）→ 提交任务
→ Next.js 后端调阿里云视觉智能 API → API 返回处理后图片
→ 存入 R2（file_type=AI_RESULT）+ 记录 ai_params → 前端展示左右对比
→ 用户确认 → 图片移入修图底片区
```

### 5.2 AI 参数配置

| 参数 | 选项 | 说明 |
|------|------|------|
| 背景色 | 白色 / 蓝色 / 红色 / 灰色 / 保持原背景 | 证件照背景切换 |
| 人物清晰度 | 标准增强 / 轻度增强 / 高度增强 | 人脸超分辨率 |
| 整体亮度 | 自动优化 / 调亮+0.5 / 调亮+1.0 / 保持原亮度 | 全局曝光调整 |
| 肤色匀称 | 标准磨皮 / 轻度磨皮 / 深度磨皮 / 不处理 | 人脸美颜 |

### 5.3 AI 任务状态

| 状态 | 说明 | UI 展示 |
|------|------|--------|
| 待处理 | 刚提交，排队中 | 灰色占位 |
| 处理中 | AI 正在处理 | 黄色旋转动画 |
| 完成 | 处理成功 | 绿色"完成"标签 + 下载/确认按钮 |
| 失败 | 处理异常（如人脸检测失败） | 红色"失败"标签 + 重新修图按钮 |

## 9. 报表模块

### 7.1 筛选维度

| 筛选 | 方式 |
|------|------|
| 快捷 | 今日 / 昨日 / 本周 / 本月 |
| 自定义 | 起始日期 ~ 截止日期 |

### 7.2 统计指标

| 指标 | 公式 |
|------|------|
| 总营业额 | SUM(amount) |
| 订单数 | COUNT(order) |
| 客单价 | 总营业额 / 订单数 |
| 已收款 | SUM(payment.amount) |
| 待收款 | 总营业额 - 已收款 |

### 7.3 图表类型

| 图表 | 内容 |
|------|------|
| 柱状图 | 每日营业额趋势 |
| 饼图/列表 | 拍摄类型占比（1寸/2寸/签证照/身份证/商务半身照/婚纱照/艺术写真/全家福） |
| 明细表 | 每日订单数、营业额、客单价、原片数、成片数 |

### 7.4 导出

支持导出 Excel（`.xlsx`），内容为每日明细表。

## 11. MVP 验收标准

系统上线后能完成以下操作闭环：

- ✅ 创建订单（客户姓名、手机号、邮箱、拍摄类型、拍摄日期）
- ✅ 上传原图（批量/拖拽上传，存入 R2）
- ✅ AI 修图（调参数 → 提交 → 左右对比 → 确认 → 存入底片区）
- ✅ 账单管理（添加产品/服务、收款记录）
- ✅ 成片管理（上传最终精修图）
- ✅ 一键邮件发送（模板渲染 + 成片附件 + 发送记录）
- ✅ 手机号查询历史订单（首页搜索入口 + 订单列表搜索）
- ✅ 客资列表（客户档案 + 历史订单数 + 累计消费）
- ✅ 今日原片集中查看
- ✅ 经营报表（日期筛选 + 汇总卡片 + 趋势图 + 类型占比 + 每日明细）
